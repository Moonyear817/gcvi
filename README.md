# 完蛋指数 · Wandan Index

一家店的经营能力已经受损到什么程度？关键问题在哪里，问题之间怎样相互拖累？

完蛋指数是一个试行中的持续经营状态评估框架：先检查致命条件，再汇总六个经营系统的风险，并保留缺失资料的状态。这里提供公开方法说明、Python 计算器、模拟算例与形式规则校核代码。

**分数描述已复核材料下的当前状态，不表示倒闭概率或剩余寿命。** 数学规则的自洽性与实际预测能力是两回事；本项目尚未完成多案例实证验证。

## 三条规则

1. **已核实的致命条件直接得到 100。** 其他方面的良好表现不能抵消。
2. **非致命状态最高为 99。** 六个系统分别判档，风险合成不采用普通平均。
3. **未知单独记录。** 致命状态未知或材料未复核时输出待补证；致命条件已排除、仅有档位或作用链未定时，输出可行范围。

六个系统依次是：现金、业务与收入、交付、团队、治理、必要经营条件。每项使用 `0 / 25 / 50 / 75 / 95` 五档；未知记为 `?`。

## 立即复算

基础计算器只需要 Python 3.9 或以上，不需要第三方库。

```sh
python3 wandan.py 75 50 50 25 25 0 --chains 5 --fatal false
```

默认采用当前推荐的 **方案 B**，结果为 `82`；原始分为 `1727/21`。命令中的 `--fatal false` 表示使用者已核实致命条件不成立，程序不会代替使用者作这个判断。

```sh
# 方案 A 保留作对照：同一组输入得到 95
python3 wandan.py 75 50 50 25 25 0 --chains 5 --fatal false --scheme A

# 业务与收入、作用链分未知：方案 B 输出 79 到 97
python3 wandan.py 75 '?' 50 25 25 0 --chains '?' --fatal false

# 已核实致命：其他项目可以未知，输出 100
python3 wandan.py '?' '?' '?' '?' '?' '?' --fatal true

# 没有指定致命状态：默认 unknown，输出 pending
python3 wandan.py 0 0 0 0 0 0
```

`--chains` 输入的是已核实作用链的**加分**（0、5、10、15），不是条数；`?` 表示加分尚未确定。`--unreviewed` 表示材料尚未复核，此时除已核实致命外不输出分数。

## 两种方案

| 方案 | 排序原则 | 代价 |
| --- | --- | --- |
| B · 当前推荐 | 先按最高单项档位排序，再在档内表达叠加 | 多项中度风险不会单靠加分跨到更高档 |
| A · v0.1 对照 | 允许其余风险把总分推到更高区间 | 可能封顶，也可能出现最高单项较低、总分反而较高 |

两种方案各有明确取舍。多个问题共同造成必要经营中断，应依据预先登记并核实的组合致命条件判定，不能临时改公式追求想要的分数。

## 校核

```sh
python3 -m unittest discover -s tests -v
```

测试包括五组算例、四舍五入、致命优先、未知范围、不可行输入，以及全部 **62,425 个可行形式状态**的基本性质、单步单调性和 B 的档位区间。形式状态计数不是企业样本量。

原研究脚本还保留参数扫描、随机三值逻辑核对和全状态两两比较：

```sh
python3 -m pip install -r requirements-research.txt
python3 enumerate_rules.py
```

完整两两比较约涉及 19.5 亿对状态，运行时间取决于设备；输出 `results.json`。日常计算无需运行这一步。

## 公开版范围

本版从原项目的书稿、数学工作稿和计算脚本整理而来，统一采用“B 推荐、A 对照”的口径。所有示例均为人工构造的档位向量，不对应具体店铺。真实案例书稿、内部聊天材料、人员对应表及个案统计未纳入此仓库。

本项目是研究与讨论中的方法原型。分档、系数与阈值仍需检验；输出应连同证据、分档和缺失项一起阅读。
